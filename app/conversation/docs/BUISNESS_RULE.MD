# 대화 도메인 비즈니스 룰

## 대화 메시지 응답

- 요청의 대화 유형은 대상 대화 세션의 유형과 일치해야 한다.
- 텍스트 대화와 음성 대화는 동일한 아바타 응답 텍스트를 기준으로 처리하며, 음성 생성 여부만 대화 유형에 따라 구분한다.
- 텍스트 대화에서는 아바타 응답 음성을 생성하지 않고 `audioUrl`을 `null`로 반환한다.
- 음성 대화에서는 아바타 응답 텍스트를 음성으로 합성하고, 생성한 오디오를 Azure Blob Storage에 저장한 뒤 `audioUrl`로 반환한다.
- 음성 합성용 프롬프트에는 여성 아티스트가 사용자에게 직접 대화를 건네는 듯한 자연스럽고 친근한 전달 방식, 감정, 말의 속도와 억양을 명확히 지정한다.
- 음성 합성용 프롬프트는 GPT가 생성한 응답의 의미와 문장을 임의로 변경하지 않고, 해당 텍스트를 자연스럽게 발화하도록 구성한다.
- 대화 맥락에 맞는 감정 표현은 허용하되 과장된 연기, 노래하듯 말하기, 불필요한 효과음은 사용하지 않는다.
- 특정 실존 인물의 고유한 음성을 복제하거나 동일하게 모사하지 않으며, 서비스에서 제공하고 사용이 허용된 여성 TTS 음성을 사용한다.
- 생성된 오디오 파일은 Azure Blob Storage의 `hanium` 컨테이너 아래 `conversation_audio/{userId}/{conversationSessionId}/{uuid}.mp3` 경로에 저장한다.
- Blob 경로의 `userId`는 현재 사용자 id, `conversationSessionId`는 요청 대상 대화 세션 id를 사용하고, 파일명은 충돌 방지를 위해 UUID로 생성한다.
- 저장된 오디오 URL은 `https://haniumstorage.blob.core.windows.net/hanium/conversation_audio/{userId}/{conversationSessionId}/{uuid}.mp3` 형식으로 반환한다.
- 음성 대화의 정상 응답은 아바타 응답 텍스트와 접근 가능한 오디오 URL이 모두 준비된 경우에만 반환한다.
- 음성 생성 또는 Blob 업로드가 실패하면 사용자 메시지와 아바타 메시지만 부분 저장하지 않도록 전체 처리를 실패로 간주한다.
