# Home 도메인 비즈니스 룰

## 알림 목록 조회

- 알림은 현재 로그인한 사용자에게 속한 데이터만 조회한다.
- 큐브 소유권은 알림 조회 범위를 결정하는 조건으로 사용하지 않는다.
- 알림 조회 유형은 `ALL`, `MISSION`, `EVENT`, `MARKET`만 허용한다.
- `ALL`은 전체 조회를 의미하는 요청 필터이며, 알림의 저장 유형으로 사용하지 않는다.
- `MISSION`, `EVENT`, `MARKET` 조회는 요청 유형과 `notification_type`이 일치하는 알림만 반환한다.
- 알림은 `sent_at` 내림차순으로 정렬하고, 전송 시각이 같으면 `id` 내림차순으로 정렬한다.
- 페이지 번호는 0부터 시작하며, 다음 페이지 존재 여부는 현재 페이지 이후의 데이터 존재 여부로 판단한다.
- 조회 결과가 없으면 오류 대신 빈 배열과 `hasNext = false`를 반환한다.
- 알림 목록 조회는 `is_read`와 `read_at`을 변경하지 않는다.
- 알림 전송 시각은 KST 기준의 offset 없는 ISO 8601 date-time으로 반환한다.

## 개별 알림 읽음 처리

- 현재 로그인한 사용자에게 속한 알림만 읽음 처리할 수 있다.
- 큐브 소유권은 알림 읽음 처리 권한에 영향을 주지 않는다.
- 존재하지 않는 알림과 다른 사용자의 알림은 동일하게 찾을 수 없는 알림으로 처리한다.
- 알림을 처음 읽을 때 `is_read`를 `true`로 변경하고 `read_at`에 현재 KST 시각을 timezone 없이 저장한다.
- 읽음 처리는 멱등성을 보장하며, 이미 읽은 알림에 대한 요청도 성공으로 처리한다.
- 이미 읽은 알림을 다시 처리할 때 기존 `read_at`을 변경하지 않는다.

## 전체 알림 읽음 처리

- 현재 로그인한 사용자의 미읽음 알림만 일괄 처리한다.
- 큐브 소유권과 알림 유형은 전체 알림 읽음 처리 범위에 영향을 주지 않는다.
- 요청당 현재 KST 시각을 한 번 생성하고 모든 처리 대상의 `read_at`에 동일한 timezone 없는 값을 저장한다.
- 이미 읽은 알림은 수정하지 않으며 기존 `read_at`을 유지한다.
- 미읽음 알림이나 알림 자체가 없어도 성공으로 처리한다.
- 전체 알림 읽음 처리는 멱등성을 보장한다.
- 처리 대상은 한 번의 일괄 수정으로 변경하고 트랜잭션을 한 번만 커밋한다.
