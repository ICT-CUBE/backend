# 큐브 도메인 비즈니스 룰

## 아바타 닉네임

- 아바타 닉네임은 사용자나 큐브 자체가 아닌 큐브 소유권에 귀속된다.
- 사용자는 현재 활성화되어 마지막으로 접근한 자신의 큐브 소유권에 대해서만 아바타 닉네임을 설정하거나 변경할 수 있다.
- 닉네임은 앞뒤 공백을 제거한 1자 이상 30자 이하의 문자열로 저장한다.
- 닉네임의 문자 종류와 중복 여부는 제한하지 않으며, 설정 후에도 변경할 수 있다.

## 큐브 코드 인증

- 큐브 인증번호가 일치하면 새 큐브 소유권과 함께 해당 소유권의 친밀도 데이터를 생성한다.
- 새로 만드는 친밀도는 `level` 테이블의 `level = 1` 데이터를 사용하고 `current_xp`는 0으로 저장한다.
- 큐브 소유권과 친밀도는 같은 DB 트랜잭션에서 저장하며, 하나라도 실패하면 전체를 롤백한다.
- `level = 1` 데이터가 없으면 서버 데이터 구성 오류이므로 공통 `500 INTERNAL_SERVER_ERROR`로 처리한다.
- 큐브 인증 성공 시 `reward_level = 1`인 모든 보상을 `UserReward`로 즉시 지급한다.
- 인증번호가 틀리면 실패 인증 이력만 저장하고 큐브 소유권·친밀도·보상은 생성하지 않는다.
