# 마켓 도메인 비즈니스 룰

## 마켓 조회

- 마켓 프로필은 현재 사용자가 마지막으로 접근한 활성 큐브 소유권을 기준으로 구성한다.
- 활성 큐브 소유권에는 하나의 친밀도 정보가 항상 존재하며, 현재 레벨은 `affinity.level_id`를 기준으로 판단한다.
- 총 거래 횟수는 현재 사용자가 구매자 또는 판매자로 참여하여 구매 확정된 거래 수로 계산한다.
- 물리 큐브는 시리얼 번호와 관계없이 `product_name`이 완전히 같으면 같은 제품군으로 취급한다.
- 제품명에는 별도 문자열 정규화를 적용하지 않으므로 같은 제품군의 큐브는 동일한 제품명을 유지해야 한다.
- 마켓 거래 이력이 있는 큐브의 제품명은 제품군과 시세 이력의 일관성을 위해 임의로 변경하지 않는다.
- 삭제되었거나 비활성화된 큐브는 마켓 제품군에서 제외한다.
- 각 제품군에서는 id가 가장 작은 큐브와 그 큐브의 마켓 상품을 대표 상품으로 사용한다.
- 대표 상품의 이미지가 없더라도 제품군은 유지한다.
- 대표 상품은 대표 큐브 id 오름차순으로 제공한다.
- 최근 체결가는 같은 제품명에 속한 모든 시리얼 큐브의 거래를 대상으로 계산한다.
- 결제가 완료된 이후의 모든 거래 상태는 체결된 거래로 취급한다.
- 가장 최근 결제 시각의 거래를 사용하며, 결제 시각이 같으면 거래 id가 큰 거래를 우선한다.
- 체결가는 배송비 등이 포함된 거래 총액이 아닌 판매글 가격을 사용한다.
- 거래가 생성된 판매글은 이후 삭제되더라도 과거 시세 계산에 포함한다.
- 체결 이력이 없는 제품군은 최근 체결가가 없는 상태로 제공한다.

## 마켓 세부 상품 조회

- 대표 큐브 id는 개별 큐브 하나를 조회하는 값이 아니라 해당 큐브가 속한 제품군을 식별하는 기준으로 사용한다.
- 대표 큐브와 `product_name`이 완전히 같은 모든 시리얼 큐브를 같은 제품군으로 취급한다.
- 아티스트명, 시리얼 번호 또는 마켓 상품 id는 제품군을 묶는 기준으로 사용하지 않는다.
- 제품군에 속한 큐브 중 삭제되지 않고 비활성화되지 않은 큐브만 판매 목록의 대상이 된다.
- 삭제되지 않은 마켓 상품에 연결된 `ACTIVE` 판매글만 판매 가능한 상품으로 제공한다.
- 판매자 본인이 등록한 판매글을 포함하여 조건을 충족하는 판매글은 별도 필터 없이 모두 제공한다.
- 판매 목록은 최근 등록된 판매글을 먼저 확인할 수 있도록 판매글 id 내림차순으로 제공한다.
- 조건을 충족하는 판매글이 없는 제품군은 판매 목록이 비어 있는 상태로 유지한다.
- 사용자 한 명은 하나의 판매글에 하나의 좋아요 상태만 가질 수 있다.
- 좋아요 수는 판매글에 연결된 좋아요 중 `is_liked = true`인 항목만 집계한다.
- 좋아요 이력이 없거나 모든 좋아요가 취소된 판매글의 좋아요 수는 0이다.
- 좋아요 취소 시 이력을 삭제하지 않고 `is_liked = false`로 상태를 변경한다.

## 판매글 상세 조회

- Path의 `sellListingId`로 판매글을 조회한다.
- 해당 id의 판매글이 존재하지 않거나 `deleted_at IS NOT NULL`이면 `404 SELL_LISTING_NOT_FOUND`를 반환한다.
- 판매글 상태가 `ACTIVE` 또는 `SOLD`인 경우 모두 상세 내용을 조회할 수 있다.
- 판매글의 현재 상태는 `status` 필드에 `ACTIVE` 또는 `SOLD`로 반환한다.
- 판매 이미지에는 해당 판매글과 연결되고 삭제되지 않은 `listing_media` 데이터를 모두 포함한다.
- 판매 이미지는 `listing_media.id` 오름차순으로 반환하며, 등록된 이미지가 없으면 빈 배열을 반환한다.
- 판매자 정보는 판매글을 등록한 사용자의 닉네임과 프로필 이미지 URL을 사용한다.
- 판매글 정보에는 제목, 설명, 가격, 등록 시각을 포함한다.
- 제품 정보에는 판매글의 마켓 상품과 연결된 큐브의 제품명과 시리얼 번호를 포함한다.
- 현재 사용자와 판매글 작성자가 같은지는 `isMine`으로 반환한다.
- 프론트에서 거래 진행 버튼을 활성화할 수 있는 조건은 판매글이 `ACTIVE`이고 `isMine = false`인 경우이다.
- 본인의 판매글도 상세 조회는 가능하지만 거래를 진행할 수는 없다.
- `SOLD` 상태의 판매글은 상세 조회는 가능하지만 거래를 진행할 수는 없다.
- 좋아요 여부와 좋아요 수는 판매글 상세 조회 응답에 포함하지 않는다.
- 마켓 상품의 별도 상태 값은 응답에 포함하지 않는다.

## 마켓 검색 결과 조회

- 검색 키워드는 Query의 `keyword`로 전달받으며 필수값으로 처리한다.
- 검색 전 키워드의 앞뒤 공백을 제거하고, 제거한 결과가 빈 문자열이면 공통 `400 INVALID_REQUEST`를 반환한다.
- 큐브의 `product_name` 또는 `artist_name` 중 하나라도 키워드를 포함하면 검색 대상 큐브로 판단한다.
- 문자열 검색은 부분 일치 방식으로 처리하며, SQL 조회 시 `LIKE %keyword%` 조건을 사용한다.
- 키워드에 LIKE 와일드카드(`%`, `_`)나 이스케이프 문자(`\`)가 들어오면 이스케이프해
  와일드카드가 아닌 일반 문자로 검색한다.
- 현재 DB의 `utf8mb4_unicode_ci` 문자열 비교 규칙을 따르므로 영문 키워드는 대소문자를 구분하지 않는다.
- 제품명과 아티스트명이 모두 검색 조건을 만족하더라도 같은 판매글은 한 번만 반환한다.
- 삭제되었거나 `status = DISABLED`인 큐브는 검색 결과에서 제외한다.
- 삭제되지 않은 마켓 상품과 연결된 판매글만 검색 결과에 포함한다.
- 판매글은 `status = ACTIVE`이고 `deleted_at IS NULL`인 판매 중인 항목만 반환한다.
- 판매자 본인이 등록한 판매글도 검색 조건을 충족하면 결과에 포함한다.
- 판매자 닉네임은 판매글 작성자의 `user.nickname`을 사용한다.
- 좋아요 수는 판매글에 연결된 좋아요 중 `is_liked = true`인 항목만 집계하며, 해당 항목이 없으면 0으로 반환한다.
- 검색 결과는 판매글 id 내림차순으로 정렬하고 페이지네이션 없이 전체 반환한다.
- 검색 조건을 만족하는 판매글이 없으면 오류를 반환하지 않고 `sellListings`를 빈 배열로 반환한다.

## 내 거래 내역 조회

- 현재 사용자가 구매자로 참여한 거래만 조회하며, 로그인 구현 전에는 사용자 id 1을 사용한다.
- 거래 상태와 관계없이 구매자로 참여한 거래 전체를 조회한다.
- 판매글이 삭제되었거나 판매글과 연결된 마켓 상품이 삭제된 거래는 조회 결과에서 제외한다.
- 거래 내역은 `trade.paid_time` 내림차순으로 정렬한다.
- `paid_time`이 같은 거래는 `trade.id` 내림차순으로 정렬한다.
- 페이지네이션을 적용하지 않고 조건에 맞는 거래 전체를 반환한다.
- 모든 거래에는 `paid_time`이 반드시 존재한다고 가정한다.
- 결제 날짜는 `trade.paid_time`의 날짜를 한국시간 기준 `YYYY-MM-DD` 형식으로 반환한다.
- 상품 이미지는 판매글에 연결된 삭제되지 않은 `listing_media` 중 id가 가장 작은 데이터의 `image_url`을 사용한다.
- 판매글에 삭제되지 않은 이미지가 없으면 `productImageUrl`은 `null`로 반환한다.
- 큐브 제품명과 시리얼 번호는 판매글의 마켓 상품과 연결된 큐브 정보를 사용한다.
- 가격은 배송비 등이 포함된 `trade.total_price`가 아니라 판매글에 등록된 `sell_listing.price`를 반환한다.
- `trade.status = COMPLETED`이면 화면 표시용 `status`는 `COMPLETED`로 반환한다.
- `trade.status`가 `PAID`, `SENT`, `SHIPPING`, `DELIVERED` 중 하나이면 화면 표시용 `status`는 `IN_PROGRESS`로 반환한다.
- 각 거래에는 주문 상세 조회에 사용할 거래 id를 포함한다.
- 조회 결과가 없으면 오류를 반환하지 않고 `trades`를 빈 배열로 반환한다.
- 공통 오류를 제외한 별도 오류 응답은 정의하지 않는다.

## 거래 진행 정보 생성

- 거래의 구매자는 API를 호출한 현재 사용자로 결정하며, 로그인 구현 전에는 사용자 id 1을 사용한다.
- 프론트에서는 구매할 판매글의 `sellListingId`, 구매자 연락처와 배송 주소만 전달한다.
- 결제 금액과 결제 시각은 프론트 요청값을 신뢰하지 않고 서버에서 결정한다.
- 판매글은 `status = ACTIVE`이고 `deleted_at IS NULL`인 경우에만 거래할 수 있다.
- 판매글에 연결된 마켓 상품과 큐브가 존재하고 삭제되지 않았으며, 큐브가 비활성화되지 않은 경우에만 거래할 수 있다.
- 판매글 또는 연결된 마켓 상품·큐브가 거래 가능한 상태가 아니면 `404 SELL_LISTING_INVALID`를 반환한다.
- 하나의 판매글에는 하나의 거래만 생성할 수 있으며, 기존 거래가 존재하면 `409 TRADE_ALREADY_EXISTS`를 반환한다.
- 사용자는 자신이 등록한 판매글을 구매할 수 없으며, 이를 시도하면 `409 SELF_TRADE_NOT_ALLOWED`를 반환한다.
- `trade.buyer_phone_number`와 `trade.buyer_address`에는 요청으로 받은 값을 저장한다.
- `trade.total_price`는 DB에 저장된 `sell_listing.price`에 5%를 더해 계산한다.
- 최종 결제 금액 계산 결과 원 단위 미만의 소수점이 발생하면 버림 처리한다.
- `trade.paid_time`은 거래 생성 시점의 한국 표준시(KST)를 offset 없는 date-time으로 저장한다.
- 거래 생성 시 `trade.status`는 `PAID`로 저장한다.
- `trade.sent_time`, `shipped_time`, `delivered_time`, `completed_time`은 `null`로 저장한다.
- 거래가 생성되면 해당 판매글의 `status`를 `SOLD`로 변경한다.
- 거래가 생성되면 판매글의 마켓 상품과 연결된 큐브의 `status`를 `TRADE_PENDING`으로 변경한다.
- 거래 생성, 판매글 상태 변경, 큐브 상태 변경은 하나의 DB 트랜잭션으로 처리하며 하나라도 실패하면 전체 작업을 롤백한다.
- 정상 처리되면 서버가 계산한 `totalPrice`만 응답한다.
